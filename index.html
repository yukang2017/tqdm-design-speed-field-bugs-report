issues.md 里的问题：需要对 nanolize 改动的 bug

这一节只列需要改 nanolize 的 bug，共 1 条。文档写明的行为、设计内的行为、环境问题和我自己的输入问题都在下一节。

没有改 nanolize 的代码，没有建本地绕过分支，没有向任何远端推送。没有关掉任何检查，没有放宽任何验收标准。

B1

作业恢复并成功结束后，状态记录里仍留着中断时的 error

✕ bug 作业状态记录 · 集群中断后恢复才暴露 · 不影响作业结果
恢复后运行中： "status": "running", "phase": "refactoring", "error": "Execution worker is no longer running."
成功结束后：   "status": "succeeded", "phase": "completed", "resume_available": false, "error": "Execution worker is no longer running."

worker 被终止后，nanolize 把这条错误写进作业记录。清掉这个字段的代码只在“暂停”那条路径里，注释写着暂停不是失败、上一次启动的错误不该留在记录上。从 failed 状态恢复不走那条路径，之后的每次状态更新和最后的成功交付也都不清它。

影响：一个成功的作业，状态里带着一条错误文字。选择页的作业面板只要看到这个字段就按错误显示，不看状态；读 job-status 的脚本或 agent 也容易据此误判作业失败。

位置：src/nanolize/execution.py 里写入 error="Execution worker is no longer running." 的地方和 _paused()；src/nanolize/assets/execution.js 第 112 行。需要的改动：恢复被接受时，或作业重新进入运行、以成功结束时，清掉这个字段。
